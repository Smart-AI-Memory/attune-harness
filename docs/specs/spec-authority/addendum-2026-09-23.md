[The decision note](README.md) is a dated record and is not edited. This file

[the Phase 3 design note](../phase-3-design.md) merged (#87). The memory

## D20: the Phase 3 decisions on the journey, the plugins, Windows and the order

The Phase 3 design note named ten decisions. At about 05:55 UTC Patrick
pasted the ten and answered "proceed as recommended". The six that belong to
the spec authority, the plugins spec and the plan are recorded here under the
note's numbering, so that "D20.8" names the Windows ruling; the four on
memory are D21.

**Decision 1, 3.1 keeps the bridge's words.** The refusal texts, the
readiness check and the import receipts are contracts and stay as written;
the class and module names are scaffolding and may change. `spec_bridge.py`
shrinks to the legacy reader, `plan_content` and `legacy_plan`, under the
name `spec_legacy.py`, with the reader tests following it; `WorkSpecBridge`,
`import_plan` and `reimport_plan` move beside `work_cli`.

**Decision 2, the R2 journey runs in the release gate.** Plan, accept, build
and review run from the `--no-deps` wheel with `attune` blocked, in the
release gate's installed check, so the gate proves the journey the README
claims as it now proves memory. The journey is also written down as a test
and as a document.

**Decision 3, 3.2's fixture comes from a real project.** One plan from
attune-ai's own `.claude/plans/`, copied with its origin and commit recorded,
plus the seven Harness plans from the Task 2 differential as the regression
set. Read and convert, never write back (D4); a receipt per conversion.

**Decision 7, 3.5 is signing plus a capability list plus a subprocess, not a
sandbox claim.** The plugins spec says what the boundary is and is not. The
README already says Harness is not a security sandbox, and the spec does not
make it one by implication. The spec is reviewed as `src/` is, before any
implementation; the implementation is Phase 4's 4.3.

**Decision 8, Windows.** Windows is a documented limit at 1.0: `fix` and
`test` unqualified there, the native memory reader refusing, WSL2 named as
the route to the POSIX profile. Phase 4's 4.2 is therefore one cycle, the
written decision and the qualification table, not the four to six that
qualifying would take; nothing on the ladders needs it before 1.0. This
supersedes the plan's instruction to make the decision "early, in Phase 2":
it is made now, at the start of Phase 3.

**Decision 10, order.** The 3.1 design detail and 3.5's threat model first,
in parallel, since neither touches the memory modules; 3.3 once Patrick's
`memory serve` observations are in; 3.2 and 3.4 after 3.1 lands.
