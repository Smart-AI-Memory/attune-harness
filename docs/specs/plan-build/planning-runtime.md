# Task 3 — bounded planning and participant assignments

Planning operates on a draft `feature-work-v1` record. Known missing goal/scope/
criteria, material answers and choices use existing attune-forms rendering and
collection. Partial supplied answers persist; unknowns remain unresolved. Complete
requests do not repeat intake. Alternatives retain rationale, evidence, uncertainty
and counter-cases; a participant cannot select a new choice or rewrite a settled one.

The existing ReviewExchange gains an explicit `feature-planning-v1` profile.
Planner maps to the native lead role and critic to reviewer only on this profile.
The declared role remains in the request and receipt. The legacy review profile is
unchanged. Native participants supply the substantive payload; the host wraps its
correlation metadata. Commands retain the existing programmatic action envelope.
No tools, review evidence policy or implicit fallback are granted by planning.

One planner and optional distinct critic use the configured identities, output
contracts and budgets. The shared dispatch, supervised subprocess, RecoveryCursor
and RunStore owners retain attempts and failure evidence. External execution and
native execution need explicit host permissions; the current qualification uses
local fixtures and injected native transports only. No provider/model trial runs.

Planning results remain attributed proposals. Exact goal retention, criterion
coverage, ordered dependencies, scope and response meaning are checked. Those
checks cannot establish semantic entailment of arbitrary task prose. Critique
findings cite evidence; optional advice stays separate. High findings prevent
staging. An unconfigured required planning hook stops before any participant call;
generic hook execution remains Task 4 work.

The planning journal is an optional, validated projection inside the same task
record. Work authority remains draft while planning runs. Host staging copies only
the current validated tasks and unresolved choices into a new draft revision,
retaining the old conversation in revision history. Staging cannot refresh away a
changed source/configuration snapshot. It does not accept the plan or write its
proposed files. The existing Spec projection can accept the resulting clean draft;
the actual collector bridge remains Task 6.

Paused completed calls are consumed without redispatch. Transport failure or a
lost acknowledgment retains an uncertain attempt and blocks blind retry/correction.
Reconciliation and broader intervention controls remain later tasks; this slice
does not invent a recovery authorization. Source freshness is checked before and
after participant work; filesystem inputs are not locked by the task-store lease.

Timing measures backend readiness of the first useful host question or validated
proposal and total active call time. It includes local intake/freshness work, but
does not measure desktop rendering, network-native performance or human reply time.

The small necessary contract extension retains planning receipts in revision
history while preserving prior accepted records. Generic execute/status routes
reach draft planning; accepted feature work still refuses build execution until
the later runtime is qualified. Plan/build CLI registration remains Task 7.
