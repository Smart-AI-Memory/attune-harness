# Narrow Luna eligibility — experiment design

September 18, 2026. Patrick said “run” after the recommendation to test a narrow
Luna eligibility rule and route the rest to Sol. Local preparation is authorized.
The earlier allocations are closed; the new concrete spend estimate requires
its existing decision before native dispatch. This is a disposable experiment,
not a product router, Task 8 acceptance or a release.

## Question and candidate rule

Can a pre-call structural rule retain every observed repair success while using
Luna for a useful share of work? Freeze the rule before any new worker response.
The routing input is a host-declared single target function, the current source
digest, explicit expected behavior, and the two available check artifacts. These
are fixture contracts, not automatically inferred understanding of arbitrary
user requests. Missing/stale required evidence blocks dispatch to either model.

For valid inputs, select Luna only when the source contains exactly one ordinary
undecorated synchronous function (the declared target), imports, a module
docstring and literal scalar constants. The function must contain no nested
functions/classes, async/yield, global/nonlocal, or try/with control flow, and at
most twelve statement nodes. Everything else selects Sol. Twelve is a proposed
conservative boundary, not a threshold learned or validated by earlier results.
Names, CLI labels and argparse imports are not routing features. The entire
source is still returned under the existing full-file response contract.

This rule cannot certify difficulty or guarantee a pass. In particular, a short
function can contain subtle requirements, and a larger module can be easy.
Defaulting more work to Sol can erase the savings. Both models retain identical
acceptance requirements, including session semantic inspection.

## Cases and qualification

Use four new behavior families: timezone-aware half-open windows, explicit false
versus absent configuration, CSV quoting, and removal of one terminal suffix.
Each has an isolated version and a version embedded with useful unrelated
serialization, async and record-handling behavior. The requested repair and its
functional checks match across each pair. Eight cases × two repetitions × two
workers = 32 proposed calls. Source variants are related, not independent tasks.
This is an initial falsification experiment; a clean outcome earns further
qualification, not production reliability.

Before paid calls: intact baselines pass; defects fail actual tests; reference
repairs pass the existing installed Spec/build/retest/resume path; changed-but-
unfixed replies and correct repairs with preservation regressions are rejected.
Protected checks compare AST outside the target and its interface against the
frozen source. The preservation requirement is in each worker's objective.
Equivalent implementations inside the target body remain acceptable. Exercise
missing/stale evidence, boundary counterexamples and injected transport without
model dispatch. Preserve earlier source, receipts and live stores.

## Frozen analysis and stop conditions

Run Luna and Sol on every case for matched comparison, even where the rule picks
one. Record routes before replies and score original replies without retries.
Report always-Luna, always-Sol and fixed-rule selections across the same paired
responses; label these policy replays, not separately deployed journeys. The
primary continuation floor is all eight Luna-selected attempts and all sixteen
selected attempts passing, no preservation miss, and at least 25% lower worker
credits than always-Sol. If either model fails a selected reply, the policy
fails the floor. Also report Sol-selected cases where Luna passed: unnecessary
escalation may undermine the rule even when the floor passes. Report every case,
total cost including failures, model latency, and classifier runtime separately.

Known ordinary failures count without retry. Stop on unknown usage/dispatch,
authentication ambiguity, input drift, host enforcement failure or exhausted
call/credit allowance. Use high reasoning and Standard service, one response,
no tools, ChatGPT authentication and no API dollars. Astra grades in this session;
that review is neither independent nor blinded and its usage is outside the
worker ledger. Native final review and the connected product journey remain
separate qualification work.

Rejected alternatives: changing production routing now would overstate evidence;
another import proxy repeats the demonstrated confounding; Luna-then-Sol retries
answer a different question and obscure the requested direct-routing comparison.
