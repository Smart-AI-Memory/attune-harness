## Question

Does Luna preserve complete real modules while repairing specific bounded
behavior defects, including cases with two interacting defects? This tests a
broader candidate scope; it does not adjust or validate the previous filter,
measure a Luna-to-Sol fallback, or imply production routing.

Twenty distinct seeded repair scenarios use twelve current Harness modules,
6,870–14,093 bytes each. The modules are retained in full. Defects are deliberate
mutations of working source, not twenty naturally discovered product bugs.
Seven cases contain two seeded defects. Several scenarios share a source module;
forty outcomes are not forty independent tasks. Two original attempts per case
use a seeded, frozen order and identical case turns. Only Luna competes.

Coverage includes Markdown escaping, public async/function/class inventories,
numeric and context bounds, duplicate-key/UTF-8 JSON validation, exact field sets,
text preservation, identifiers, recursive globs, repository exclusions, SQL literal
escaping, rank fusion, provider usage, module/path handling, observed test outcomes,
substantive prose and Unicode paragraph offsets. This is bounded function repair
inside larger files, not multi-file implementation or arbitrary difficult work.

## Controls and grading

Each case declares exactly one target function and one writable full file.
Only the target body may change. Four supplemental tests cover requested behavior;
four protected tests include additional behavioral checks, the complete unrelated
module AST and the target signature. Equivalent body implementations are allowed.
AST preservation does not prove every runtime behavior, and comments/formatting
alone do not fail it. Session semantic inspection precedes execution of every
original proposal and remains a separate requirement.

Before native dispatch, all twenty intact modules must pass; each seeded module
must fail both suites; twenty reference repairs must complete the actual installed
Spec/build/retest/resume path. Twenty unfixed controls, twenty unrelated-code
changes and twenty interface regressions must be rejected. Exercise the forty-slot
transport with an injected process and one full wrapper-to-check replay, with zero
provider calls. Preserve earlier receipts and current product source.

Tests load the proposed full module from its fixture and import dependencies from
the qualified installed package, whose source files are explicitly hash-bound.
Workers receive current source, objective and failing evidence, not reference
solutions, the local mutable checkout or tool access. Native cwd is an empty temp
directory; the inner sandbox is read-only. The existing response contract is kept,
including strict rejection of malformed originals. Transport errors are not
repaired into passing replies.
