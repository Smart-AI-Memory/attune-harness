# Task 2 — shared work contract

`feature-work-v1` uses the existing task envelope, RunStore lock/checkpoint and
profile dispatch. It retains intent, focused unanswered questions, genuine design
alternatives, authoring reasons, declared assignments, ordered dependent tasks,
required/advisory controls, source/artifact identities and prior revisions.

Selection follows the existing collaboration contract and XML eligibility:
continuity, unresolved design or consequential decisions require a spec; cold
handoff, dependencies, authorization/data/compatibility risk or an XML consumer
require XML. Otherwise a complete bounded request uses a prompt. Existing XML/spec
consumer requirements cannot be downgraded. No file-count cutoff is used.

This module consumes structured facts; it does not claim to discover intent from
natural language. Missing goal, scope or acceptance criteria and material questions
or unselected choices remain explicit. Corrections merge supplied fields, preserve
other answers, and invalidate authority only when content/evidence changes.

Acceptance is a trusted host projection of an existing Spec decision, never a new
human gate or a model verdict. The projection binds the work ID, revision, complete
request, storage owner and pre-decision checkpoint. Its source reference is audit
context, not a cryptographic credential. Task 6 must qualify the actual collector
bridge; until then the Python API is exercised by synthetic trusted-host fixtures.
Hashes detect stale/corrupt records within that host boundary, not malicious local
writers who can replace the entire store.

Required controls must have an exact supported owner/kind/version at acceptance;
unknown advisory controls remain visible. Availability is not execution evidence.
No record in this contract-only slice grants provider calls or filesystem effects.
The existing execution route must reject this profile until its runtime is ready.

Falsifiable checks: retain supplied intent; choose the expected tier for frozen
cases; reject partial, stale, copied and replayed decisions; preserve old readers;
block unknown required controls; detect changed source/config/artifact; preserve
accepted history through correction. Remove selected guards in an isolated copy
and confirm the associated negative test fails. No paid/native trial is needed.
