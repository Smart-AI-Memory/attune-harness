# Historical documentation archive

Use this archive to find instructions and evidence for an older version. These
records retain their original paths, headings, commands and evidence identities
so existing citations and bookmarks continue to work. They are not instructions
for a newly selected 1.5.1 candidate.

For a package-index installation, use the [published 1.5.0 package reference](https://pypi.org/project/attune-harness/1.5.0/).
The [1.5.1 documentation audit](../documentation-audit-1.5.1.md) identifies the
separate preparation guides and their integration gates. Publication of 1.5.1
has not been verified.

## Dated evidence, designs and decisions

The [documentation index](../README.md#dated-evidence-and-design-notes) retains
the dated results, receipts, design notes and research. Specifications retain
their own approval and implementation status. An accepted design is not a
claim of released behavior.

The [file inventory](../documentation-audit-1.5.1.json) lists all tracked Markdown
and HTML prototypes in the audited documentation candidate, their categories and
SHA-256 identities. Dated evidence and original prototypes remain in place;
archiving does not rewrite a test result, regenerate a receipt or qualify a new
artifact.

## Training exports and captures

Earlier PowerPoint decks, HTML training copies, screenshots, source snapshots
and worksheet receipts keep their original version labels. The Harness
repository contains the versioned Markdown procedures and five HTML prototypes;
it does not contain the separately retained editable decks. Their locations and
unverified publication coverage are recorded in the audit.

Keep new observations beside old observations and identify the selected source
and artifact. A metadata-only 1.5.1 validation wheel does not turn 1.5.0 captures
or earlier candidate runs into 1.5.1 release evidence.
