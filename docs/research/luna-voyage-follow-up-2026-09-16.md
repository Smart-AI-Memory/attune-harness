## New information from the stopped trial

The [original calibration](../voyage-answer-accuracy-calibration-2026-09-15.md)
retains one completed Luna question pair, graded correct in both conditions,
and a later inspection-stage failure. No new model calls were needed to examine
the recorded failure and compare its environment with successful stages.

The native output schema in the frozen `transport.py` only requires an object
containing a string named `text`. The workflow separately asks that this string
contain an `actions` object during inspection. Therefore a prose answer can
satisfy the enforced outer schema while violating the inspection contract.
This is a demonstrated gap in the experiment's response contract, not proof that
a stronger schema will make future model actions meaningful or correct.

An offline analysis of the saved native replies found:

| Recorded requested route | Native replies examined | Outer shape valid | Inspection replies with the required top-level shape |
|---|---:|---:|---:|
| Astra | 40 | 40 | 20 of 20 |
| Luna | 10 | 10 | 5 of 6 |

The code-mode, skill-budget and under-development warnings appeared in all
20 shape-valid Astra inspections, all five shape-valid Luna inspections and the
failed Luna inspection. Their presence does not distinguish failure from
success. This observation neither proves they caused the failure nor rules out
an interaction with the model or prompt. Do not attribute a model-only cause.

These are response-shape counts from a stopped, unequal sample, not comparative
accuracy or reliability estimates. They do not validate the individual actions.
Two legacy Luna replies were decoded using the recorded v2 decoder without
dispatch; saved source, prompts, replies, grades and ledgers were unchanged.
Two other receipts without decoded identity were excluded explicitly.

## Questions and comparisons

| Question | Comparison that can answer it | Evidence to retain |
|---|---|---|
| Can Luna follow the workflow reliably? | Current text envelope versus a schema for the actual inspection actions and a separate answer schema, with model, host settings and task fixed | Stage completion, malformed or premature replies, valid-but-useless actions, corrective attempts and final correctness |
| Does Voyage improve Luna's memory work? | Same fresh tasks with and without Voyage evidence; hold revision and verification behavior constant rather than changing them with retrieval | Correct facts and decisions, source support, useful recall, preserved exceptions, harmful omissions or merges, appropriate uncertainty |
| Where does evidence selection matter? | First give models identical evidence packets; separately test model-authored queries or changed passage selection only when observed errors justify it | Missing relevant passages versus misinterpreting supplied passages; performance with conflicting, outdated or irrelevant evidence |
| Does routine delegation save time and cost? | Current lead-managed work versus the bounded worker, including retries, checking, retrieval and escalation | Time to useful result, full completion, lead/human correction, tokens, provider charges where known and subscription quota separately |

The second comparison must include memory tasks, not only repository questions.
Cases should cover an explicit preference correction, a decision versus a
suggestion, similar records with different exceptions, an unsupported inference,
conflicting dated evidence, and a missing source. Keep canonical source material
available so summarization cannot silently replace its meaning.

## Experiment sequence

1. **Qualify the response contract offline.** Use saved failures as regression
   examples, then separate operational fixtures. Stage schemas must reject the
   observed malformed response; admissible actions still need scope and semantic
   checks. A valid empty actions list must not count as successful inspection by
   itself. Retain the original controller and failure receipts.
2. **Compare native stage behavior.** Change the response contract while holding
   the selected host profile and task fixed. Record warnings and configuration.
   Any host-configuration comparison is a separate factor with equivalent required
   controls; changing both at once would obscure attribution. A different protocol
   gets a versioned experiment, never patched results in the stopped campaign.
3. **Compare memory outcomes.** Start with Luna and the existing lead baseline on
   identical evidence. Include Haiku as the agreed comparison when its route is
   qualified. Freeze fresh cases and scoring before evaluation; keep evidence
   completeness separate from answer correctness. A grader who authored the
   cases is not independent, and label masking has limits.
4. **Evaluate delegation economics.** Use measured work and correction costs to
   define the useful worker scope. Include all failed and escalated attempts.
   API price tables do not convert Codex subscription usage into dollar charges.

Before new live comparisons, specify the exact profiles, sample size, budget,
retry policy and acceptance criteria in the experiment packet. Existing spend
and execution rules apply. Thresholds should follow the observed baseline and
task consequences, not an invented percentage improvement. The offline analysis
above and the bounded follow-up establish no live gain or production routing change.

This research should benefit shared retrieval, grammar and memory interfaces
first, with Harness integration next. A documented Harness release blocker still
outranks optional shared enhancement. These open research questions are not newly
declared release blockers.
