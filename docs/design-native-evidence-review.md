# Native evidence review — repair after the first Astra run

The authorized dev8 test invoked Astra three times. Retrieval and verification actions passed. The final review correctly identified the contradictory worker-success policy and preserved cost uncertainty, but its copied request digest ended in an ellipsis. The existing correlation guard correctly rejected it. The first run, raw native output and dev8 package remain intact; rejected text is not reclassified as an accepted response.

Design: add explicit native `review_mode: evidence` to the workspace profile. The host schedules exactly retrieve, verify, then final review under the existing accepted tool/turn budgets. Only final review invokes the model. Use the existing source projection to send the whole document, distinct retrieved references and scoped verifier findings, excluding request hashes, action protocol and peer narratives. The existing NativeExchange/JsonParticipant already binds the native invocation and its reply in code. Construct the outer review action and current-turn digest in the host after the native response passes that boundary. Do not accept or repair a model-supplied digest. Label the narrative an unverified proposal and retain the normal transport limits, error propagation and no-fallback behavior.

Cases: host evidence steps use no model; both roles invoke exactly once; incoming request digest, ordered history and budgets are checked before dispatch; no self-corroboration or peer output is projected; invalid/absent references and empty/oversized native results fail; model/effort still reach argv; changing review mode invalidates prior acceptance and continuation. Native mode omission preserves dev8 for explicit historical reproduction.

Validation: new behavioral tests and targeted mutation checks, full suite, fresh dev9 installed wheel, and a new accepted run on the exact already-approved synthetic document/reference bytes. At most two further model invocations (five cumulative, within Patrick's six-call approval). There are no automatic retries. The new run is an explicitly changed contract, not a continuation of the failed accepted run. A successful smoke review does not qualify general accuracy.

Rejected alternatives: copying or truncating hashes remains model bookkeeping; replacing a wrong returned digest after receipt would hide the failure; spending Astra calls to request two predetermined tools adds avoidable cost. Global Codex settings and credentials stay unchanged.
