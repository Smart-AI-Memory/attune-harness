# Task 8 — response-contract repair and local qualification

The bounded contract repair is implemented and locally qualified. **Task 8 is
still open for fresh native outcome and connected-journey evidence.** No additional
native calls, active installation changes or live memory operations were made.
The original 24-call comparison remains a failed result, preserved byte for byte.

## What changed

- New planning and build journals use response-contract version 2. Old journals
  retain their original prompts, decoding and event bindings. Changing a populated
  journal's response version invalidates its dispatch evidence.
- New workers return version 2 and file proposals. The host supplies the accepted
  step identity and dependencies; workers no longer choose or copy those IDs.
  Each output template includes the exact permitted path and expected preimage
  SHA-256, or null for creation. The model authors content; the host checks scope,
  hashes, current source bytes and authority independently.
- Plans map exact criteria to actual tasks and supply concrete checks. The host
  inserts the bound criterion text when staging the next draft; the raw proposal
  remains unchanged in history. Staging grants no acceptance or file-write authority.
- Planner/critic and worker/reviewer prompts have separate schemas. Planning
  exposes and validates the supported ordered build shape. Routine alternatives
  belong in notes; real unresolved human choices still require decisions.

The repair uses existing work records, transport, Spec collection, file effects,
protected checks and task handoffs. It adds no commands, router or gate system.
Legacy worker replies still undergo the exact original ID/dependency checks;
the host does not silently reinterpret previously rejected version-1 replies.

## Problems found during verification

The first new compatibility tests attempted a zero-operation pause, which the
existing journal correctly refuses. The fixture now creates an original-contract
record before its first event and pauses at a real supported boundary.

The first wider source command used a relative Python path. Subprocess fixtures
changed directory and loaded an older installed CLI, producing setup errors.
Absolute source paths resolved that environment mistake. The old runner test was
also tied to the completed campaign's source hashes; those correctly rejected
this source revision. Its injected-process test now prepares a fresh local packet
instead of rewriting the historical experiment or bypassing freshness validation.

One initial guard-removal trial was masked by another criterion check. Targeting
a foreign task reference isolates the intended guard; all six final trials fail
for their expected protection removal. The first installed fixture omitted two
participant configuration files needed by the older campaign tests. The complete
fixture passes. Original failed runs remain retained alongside the passing ones.

No independent native reviewer or provider-backed quality pipeline ran during
this correction. Local qualification supports the repaired mechanics; it does
not demonstrate that models will obey the revised prompts.
