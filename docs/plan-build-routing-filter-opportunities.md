# Python intake filtering: evidence-backed opportunities

September 18, 2026. Analysis of existing evidence only; no new trial, routing
change or Task 8 acceptance. The main comparison's original grades and 27/27
candidate floor stay fixed. The separate [pilot report](receipts/plan-build-repair-contenders-native-2026-09-18/side-pilot/results.md)
is retained with its original evidence.

**Keep deterministic intake, but do not adopt the argparse-import rule.** Its
four new cases pass with either model, with identical repairs. The rule selects
2.986188 worker credits versus Luna's 0.375167, saving only 6.735 summed native
seconds in this sample. It misses a delegated parser and flags an unused import.
These are paired-response selections, not measured deployed routing savings.

## 1. Missing required evidence or authority: request it before a worker

- **Observed evidence:** `b_missing_evidence` and `b_pending_choice` in the
  [memory-routing v2 grades](receipts/memory-routing-v2-2026-09-16/grades.json).
  Coarse escalation called Astra after Luna already identified the unresolved
  need; the stronger call added no information. Distinct dispositions avoided
  two such calls. [Measured policy results](research/memory-routing-v2-results-2026-09-16.md).
- **Available before dispatch:** required artifact IDs, readable supplied
  artifacts, current source hashes and accepted decision receipts, when the host
  contract actually declares them. Python can check their presence, validity and
  freshness reliably. It cannot reliably infer an unstated evidence requirement
  or distinguish an unmade decision from an unavailable decision using keywords.
- **Proposed action:** obtain the specific missing evidence or human decision;
  stop stale/invalid requests at the existing host boundary. Do not pay Sol or
  Luna to invent the absent fact. This extends a known control idea, not a proven
  pre-call classifier: the live v2 experiment used model interpretation to find
  these needs, so zero-call detection itself still needs qualification.
- **Counter-case:** a referenced file may be optional or superseded. A crude
  missing-file rule would block work that already has sufficient evidence.
- **New validation case:** a package-migration request with one missing required
  compatibility receipt, one absent optional attachment and one superseded
  decision. Verify that only the required gap blocks, then supply it and resume
  without changing scope or granting stale authority.

## 2. Full-file replacement with substantial unrelated behavior: test direct Sol

- **Observed evidence:** original Luna `ls04`, `ls19`, `ls29` and `ls41` in the
  [main call receipts](receipts/plan-build-repair-contenders-native-2026-09-18/calls).
  The requested small corrections concern a roughly 9.7 KB module; failures
  include an unrelated async-signature regression, malformed response, changed
  punctuation and invalid Python escapes. `ls04` passes all eight tests but fails
  semantic preservation; its [separate diagnostic](receipts/plan-build-repair-contenders-native-2026-09-18/diagnostics/ls04/async-signature.json)
  confirms the regression. The main report retains all counterpart outcomes.
- **Available before dispatch:** output protocol (whole file), source bytes,
  AST declarations outside the requested region, async declarations, literal
  escape locations, and named preservation checks. Python can inventory these;
  it cannot turn a declaration count into proven difficulty or infer every
  behavior that must be preserved. Missing caller evidence belongs in item 1.
- **Proposed action:** use Sol for the next already-defined broad repair
  qualification where the frozen floor supports it. For a future intake rule,
  test preservation surface independently of CLI labels and raw length. No
  numeric size threshold is earned by this dataset.
- **Counter-case:** all these failures involve the same module and related
  tasks. Luna also repairs that module successfully. A long file may be simple,
  while a short function can encode a difficult behavioral contract. The side
  pilot's short CLI repairs pass with Luna; CLI role alone is not enough.
- **New validation case:** use new asynchronous serialization code, crossed as
  short/long and CLI/library versions with equivalent requested edits and
  explicitly matched preservation requirements. Include meaningful unrelated
  behavior rather than padding. Freeze the rule before seeing replies; retain
  the same effect boundaries and grade originals. A later targeted-edit protocol
  comparison is a separate host experiment, not an assumed remedy.

## 3. Bounded repair with explicit expected behavior: keep Luna as a candidate

- **Observed evidence:** the retained nested-status case and the paired
  assertion/header cases in the main screen; the earlier
  [18-call repair screen](plan-build-repair-model-results.md); and the new pilot's
  four short cases. Both models handle these examples. The earlier screen costs
  Luna 1.123814 versus Sol 22.555440 credits for six repairs each; the side pilot
  costs 0.375167 versus 6.783580 for four each. These samples support an economic
  opportunity, not a universal success rate or proven retry economics.
- **Available before dispatch:** one accepted writable target, an exact preimage,
  observed failure output, a supplied expected schema/output, preserved test
  requirements and an available independent check. Python can validate those
  structural facts. It cannot certify that the expected behavior is correct or
  that a change is semantically routine simply because the target is a test.
- **Proposed action:** retain Luna for a future bounded worker cohort with
  explicit host controls and semantic sampling. Do not change the main screen's
  failed eligibility result or silently route all tests to Luna.
- **Counter-case:** an incorrect reference expectation can yield a convincing
  but wrong assertion repair. Two defects were not harder than one in the
  observed examples; defect count is not a supported routing feature.
- **New validation case:** a new timezone-aware event-window fixture with one
  incorrect expected boundary and a separate deliberately incorrect supplied
  expectation. Require the worker to repair the supported case and preserve
  uncertainty in the conflicting case without weakening tests.

Host/interface defects remain a separate class. The v2 memory experiment shows
four semantically correct Luna replies but only one legacy host acceptance;
host-owned version binding and an explicit unchanged policy bring acceptance to
four of four. That supports repairing the contract, not upgrading the model.
Likewise, a host-provided `known_difficult` flag demonstrates a route, not a
qualified classifier. The fully evidenced multi-step memory calculation was
solved by Luna, so neither complexity language nor a hindsight failure label is
an acceptable intake signal.

Finish native journey qualification first. If another filter experiment is
prepared afterward, use these observations to choose a single hypothesis, new
source cases for validation, and a fresh call/cost decision. No stronger router
or new paid trial follows from this analysis.
