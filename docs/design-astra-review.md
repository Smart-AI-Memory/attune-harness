# Astra review selection — design

Patrick explicitly requested switching the Harness reviewer to his selected GPT-6 Astra / extra-high setup. Outcome: new workspace reviews select `gpt-6-astra` with `xhigh` reasoning through the existing Codex CLI adapter, and retained evidence demonstrates the settings reach an actual worker. Done when the profile, adapter, accepted-request/recovery guards, tests, installed artifact and one bounded live documentation review are verified. This is model-selection implementation and a smoke test; it does not replace the frozen semantic-quality comparison.

Read-only probes: installed Codex CLI 0.153.4 supports `--model` and TOML `--config` overrides. The local model catalog lists `gpt-6-astra` and supports `xhigh`; the app's selected model/effort match Patrick's statement. Harness already supports native Codex but its closed registry and exchange have no reasoning-effort field. Existing pilot configs explicitly select Llama and historical accepted configs must remain preserved.

Add an optional Codex-only `reasoning_effort` registry field, validate supported spelling, pass it as `-c model_reasoning_effort="xhigh"`, and retain the requested setting and actual dispatch arguments in the participant identity. Omission preserves the old invocation. A changed effort changes the registry/form/checkpoint binding. Provider rejection, malformed output, missing executable and timeout remain visible failures; no model fallback. Retain the native CLI's existing sandbox and authentication path without reading, copying or changing credentials.

Create workspace `participants.json` with two distinct Astra participant identities and a 300-second per-turn timeout. New `review-form` and `review` commands default to the current directory's `participants.json`; explicit configs and explicit resume bindings still win. The profile uses native action review and does not pretend to run the Ollama-specific passage contract.

Cases: model and effort reach argv; quoted override is parsed correctly; old/Claude invocations do not acquire an effort flag; invalid/non-Codex effort fails before dispatch; profile loads; omitted CLI config resolves the workspace file; changed effort invalidates acceptance and paused continuation. Verify the actual installed CLI, retain live dispatch output, and distinguish requested settings from absent server-attested model metadata.

Rejected alternatives: relabeling an Ollama command cannot invoke Astra; relying on the app's global setting leaves the worker ambiguous; rewriting prior accepted configurations corrupts historical evidence. No new generic provider framework or agent-team changes are needed. The live smoke test uses existing Codex sign-in under Patrick's explicit switch request, with at most six native invocations, no automatic Harness retry or fallback. No credential workaround is authorized.
