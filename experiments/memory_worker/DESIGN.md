# Disposable bounded memory worker

2026-09-16. Patrick authorized carrying the repaired contract into the next
bounded worker, retaining Luna, explicit host routing and sampled semantic
review. This increment creates a runnable **proposal-only** worker with durable
host-owned job records. It does not enable production memory changes or execute
the scoping plan/build spec. Done when replayed native outputs and adversarial
controller fixtures demonstrate the lifecycle, and actual adapter limitations
are recorded from an isolated probe.

Reuse the frozen citation schema, instructions, normalizer and one-hop policy
without editing any preceding campaign. Routine assignments use Luna; the
host-declared known_difficult class goes directly to Astra. Unknown task classes
and capabilities outside synthetic_facts_v1 stop before dispatch. This explicit
class is a host input, not an inference from model confidence or source prose,
and does not establish that a particular real workload requires Astra.

The host selects semantic samples before dispatch using a stable hash of its job
ID and configured salt/bucket/modulus. A modulus of four is a demonstration
setting, not a qualified production audit rate. Sampled valid results, including
no-change/evidence/decision outcomes, are reviewed before publication. Unsupported,
uncertain, malformed or unavailable audits never yield an accepted proposal.
No audit means no stronger repeat of successful routine work. A stronger result
that still needs reasoning stops. At most three participant calls per job: initial,
one possible escalation, one sampled audit. No separate routing model.

Reuse Harness RunStore's existing short OS-backed lease and atomic persistence
for prototype job artifacts. Capture inputs, grants, host class, policy and a
monotonic generation. Release locks before participant work, then recheck current
state before every dispatch and final publication. Bind the generation too, so
change-and-restore cannot revive old work. Persist dispatch intent first; record
all replies and failures. A claimed job ID cannot be dispatched again, including
after interruption. Inspection is read-only; there is no automatic recovery or
claim of exactly-once remote execution. There is no memory apply/export method.

Boundary cases: all eight saved successful Luna tasks; direct known-difficult
routing; invalid/reasoning one-hop escalation; no redundant escalation for absent
evidence or owner choice; confident semantic error quarantine; false no-change;
audit uncertainty/invalidity/unavailability; changed input/evidence/grants/policy
during calls and before publication; ABA change/restore; competing process claims;
interruption after dispatch intent; persistence failure; malformed host inputs;
unknown capability/class; inspection/repeated job IDs without dispatch. Fixtures
must establish exact call counts and unchanged captured memory records.

Before this code: reviewed actual memory APIs and ran scratch probes. A second
Harness RunStore lease was rejected. An explicitly temporary FileStashBackend
captured a synthetic note, reopened and recalled it, forgot its exact ID, and
verified absence. The first scratch probe incorrectly passed a string to forget;
its assertion failed. Repeating with the documented list-of-IDs argument passed.
Neither probe used automatic backend resolution, live memories or provider calls.

File stash has no expected-version update/transaction interface; its source uses
locked appends and exact-ID removal. cwd is a retrieval preference, not access
isolation. Personal, raw-session, curated and security taxonomies differ; the
experimental preference/lesson kinds must not be silently passed through or
treated as security labels. The bounded real-adapter probe will preserve evidence
of duplicate-ID behavior and cross-project recall, not claim concurrency/deletion
qualification. Do not hold its age-expiring file lock across model work.

Validation uses saved native replies (exact task/schema/prompt replay) and clearly
labeled injected responses for controller faults, not new quality observations.
The replay salt is selected to exercise the sole already-recorded conditional
audit; that fixture schedule is not independent sampling evidence or calibration.
No new native campaign is needed to test this host-only increment. Run the new
and inherited suites centrally, exercise the worker from its terminal demo,
recheck prior frozen hashes and retain a reproducible receipt. A bounded read-only
review reports evidence chains; it does not replace central verification.
