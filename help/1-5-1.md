## Install Harness 1.5.1

Harness 1.5.1 is published on [PyPI](https://pypi.org/project/attune-harness/1.5.1/).
Use it to plan work, inspect evidence and return to saved progress. The browser
companion helps you save and review requests; the CLI handles execution under
its separate scope and approval rules.

Use Python 3.10 or later and a fresh environment. Keep Harness separate from
Attune AI, which pins a different MCP SDK version:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install "attune-harness==1.5.1"
python -c "from importlib.metadata import version; print(version('attune-harness'))"
python -m attune_harness
attune-harness --help
```

**Expected result:** Version `1.5.1`, a verified deterministic arithmetic receipt,
and the command catalog. The example makes no model call and measures no model
quality. For a managed CLI, you can instead use
`uv tool install 'attune-harness==1.5.1'`, then inspect `uv tool list --show-paths`.

On Windows, use `py -3 -m venv .venv`, then run Python commands with
`.\.venv\Scripts\python.exe`. For example:

```powershell
.\.venv\Scripts\python.exe -m pip install "attune-harness==1.5.1"
.\.venv\Scripts\python.exe -m attune_harness
```

This is reference syntax, not a new Windows shell qualification. Keep task
records outside checkouts used for file effects and use canonical absolute paths.

## Choose a useful next step

- [Get started](/harness/help/get-started/): check your installation and obtain the release examples.
- [Browse all goals](/harness/help/goals/): choose from 21 goals and six testing FAQs, with prompts and review points.
- [Start and continue work](/harness/help/start-and-continue/): save answers and review the request in a browser form.
- [Plan and accept work](/harness/help/plan-and-accept/): inspect scope and acceptance criteria before execution.
- [Research a question](/harness/help/research/): retrieve local sources and check a supported link claim.
- [Save and resume](/harness/help/save-and-resume/): return to saved answers and inspect work before continuing.

Preparing a request, saving answers, accepting intent and authorizing execution
are separate decisions. The goals worksheet records proposed wording; it does
not accept a spec, dispatch a model or implement the example app. Installing the
runtime does not install a host plugin or skill. Follow the selected host's
[setup instructions](/harness/help/dependencies/#integrate-with-a-host) separately.

Attune AI is deprecated. Use Harness for new work. Before changing an existing
setup, read the [migration guide](https://github.com/Smart-AI-Memory/attune-harness/blob/ebb5b03b8a4398325df7ddabd28c08186451452e/docs/migration.md).
Preserve working environments while validating the journeys you need. Deprecation
does not establish saved-work migration or complete host or Windows parity.

## Work on Windows within the documented limits

Windows users can install Harness and use its documented CLI workflows and
browser forms. Release qualification passed the hosted Windows Server source
and installed-wheel checks. Forms save and review intent; they do not build.
Native planning and building remain experimental.

Full Windows parity remains deferred. Hosted Server checks do not qualify
Windows 11 desktop, all shell journeys, complete storage/recovery acceptance or
live native-memory reliability. The saved-store contract still uses a two-second
acquisition limit, eight writers and one save per caller; durability barriers and
qualification assertions remain intact. A passing software check does not close
those broader acceptance gaps. Read the [release notes](https://github.com/Smart-AI-Memory/attune-harness/releases/tag/v1.5.1)
for the supported components and remaining limits.

## Inspect completed assessment evidence

For an existing completed document assessment, replace `TASK` with its saved
task directory and inspect:

```sh
attune-harness status TASK --format markdown
attune-harness status TASK --format html > assessment-report.html
```

Open the generated HTML report. Both formats present the accepted goal and
criteria, checker outcomes, retrieved-source identities and separately attributed
participant judgments. A successful status command does not mean the assessment
passed. Inspection does not rerun checks, refresh evidence or establish semantic
acceptance. Other profiles and incomplete assessments keep their existing
presentation. This addition is absent from published 1.5.0.

Read the [inspection procedure](https://github.com/Smart-AI-Memory/attune-harness/blob/ebb5b03b8a4398325df7ddabd28c08186451452e/docs/cli-guide.md#inspect-completed-assessment-evidence-151-candidate).
